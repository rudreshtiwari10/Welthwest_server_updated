=================================================================================
    ARCHITECTURAL DECISIONS MADE
=================================================================================

1. REDIS FOR COUNTERS
   - Atomic Lua script for check-and-increment
   - Prevents race conditions
   - Fast (<20ms typical)

2. MONGODB FOR PERSISTENCE
   - users collection: subscription data
   - plans collection: plan definitions
   - transactions collection: payment records
   - usage_logs collection: audit trail
   - webhook_events collection: raw webhook data

3. MIDDLEWARE APPROACH
   - Decorator-based: @feature_limit(feature_key)
   - Works for both anonymous and authenticated
   - Returns 403 with upgrade CTA on limit

4. PLAN CONFIGURATION
   - All from .env (no hardcoding)
   - Seeded to MongoDB on startup
   - API reads from MongoDB (fast)

5. PAYMENT FLOW
   - Backend creates Cashfree order
   - Frontend redirects to Cashfree
   - Cashfree calls webhook on success
   - Webhook verifies signature + upgrades user
   - Frontend polls or shows processing state

6. ANONYMOUS TRACKING
   - Cookie-based: ww_session_id
   - Redis counters with TTL
   - Separate limits from authenticated

7. LIMIT RESET
   - Daily at server midnight (SERVER_TIMEZONE)
   - Fixed window (not sliding)
   - Automatic via TTL in Redis
